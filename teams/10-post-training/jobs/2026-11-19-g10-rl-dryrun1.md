## Design (one question, one lever)

- **Pool.** Trained pool = #564's RL training pool (3,251 ids) minus the 18 of the 23 free-reward ids it holds (the verifier
  audit of 18 Nov: 23 tasks give full reward to a program that solves nothing, 13 of them to a statement-sample lookup) minus
  the effort-suite ids it holds (0 of 55) = **3,233**. The ids of both lists are committed
  (`capstone/rl_exclusions_v1/free_reward_ids.txt`, sha256 below; the 55 in `eval/effort_manifest.json`). The job writes the
  id lists, asserts **zero overlap** with both lists and with the held-out subset, and prints the counts. The probe's 48 easy
  ids come first (39 are trainable: 8 are held-out ids and 1 is free-reward; they must not be trained on), then the rest of
  the pool in file order.
- **Held-out.** The first 64 ids of #564's RL held-out pool (255) in file order, **unfiltered** (the free-reward and effort ids
  in it stay in; the summary reports counts). Never trained on, split by problem. 64 problems and 4 samples each, fixed by
  Amendment 2 of the preregistration from timings only.
- **Screen (the stop must be worth reading).** The first n trained prompts (the easy ids first, as #587's screen), k = 8, up
  to 1,536 new tokens. n is the largest of 64, 128, 256 that fits 10 minutes at the decode rate measured in the job (the
  rebuild's rate probe of 8 easy prompts, or a probe on the raw weights). The threshold is at least 4 mixed prompts whatever
  the size (the trainer needs a cohort). Below it the job stops with `NO_GO_MIXED_BAND` and saves `screen_survey.json`:
  pass rate with a 95% interval over problems, the histogram, the failure mix (no code, cut off, crash, wrong answer, timeout).
- **Training.** `rl-loop/train.py`, unchanged: `objective_v1`, AdamW **lr 1e-5** (the value of `task11_code_canary.yaml` and of
  the 15 Nov run; those notes call it 20 times the Deletion-Tuning authors' GRPO setting, so `stored_update_share` and the
  per-step reward trace are how this job says whether it is right here), k = 8, **16 prompts per step** (or the cohort if
  smaller), kl_coef 0 (objective_v1 has none), tr_epsilon 0.2, max_new 1,536, temperature 1, router frozen, fp32 masters.
  **At most 10 updates, on the screened mixed cohort.** On 15 Nov the whole held-out gain was there by step 10 and the next 50
  steps only fitted the 56 cohort prompts; more steps on the same cohort buy memorisation. If the result is a CI above 0, the
  next lever is more prompts (a larger cohort), not more steps.
- **Scorer.** Every program is scored through `rl-loop/score_pool.py` (`reward_pool 16` worker processes, each calling
  `stdio_check.score`); the trainer's own `require_verifier` check runs a known pass and a known wrong answer at task build.
- **Cheap tricks.** Before the model loads, the nine no-skill programs of the audit (print nothing, echo, 0, 1, -1, YES, NO,
  Yes, No) are scored on the first 128 screen candidates and the 64 held-out ids (the dry run: all 0). A held-out gain is read
  against that floor. The audit's sample-hardcode program is not rebuilt: its 13 tasks are among the 23 excluded ids.
- **Literal-sample detector (built; rule 6 of Amendment 1).** On each held-out evaluation, every passing completion is
  checked: a program that never reads stdin (`no_stdin`), or whose source holds a whole test input of 4 or more characters
  (`embeds_input`), is flagged. It is a conservative heuristic (tested on constant printers, a table lookup and a real
  solution), not proof of a hack. The decision rule uses the flagged share of passing samples at the last update against
  update 0.
- **Decision rule (fixed before any run).** "RL helps on the real checkpoint" = the paired 95% interval of the held-out change
  has its lower bound above 0, **and** the number of wrong-answer samples on held-out does not rise, **and** the literal-sample
  share of passes is not above update 0's. Otherwise the result is "the RL path runs on the real checkpoint; no measurable gain
  at this budget", and the next request moves one lever by 10x (prompts), not several.
- **What does not transfer.** The 15 Nov E1 numbers (Qwen2.5-Coder-7B, +0.100 held-out, saturated at step 10) and OLMoE
  phase C: model, tokenizer, sampler (G5 policy sampler with KV cache here), learning rate, and the scorer-pool speedup (a
  32-process A100 host). A verdict here is about a weak T2 checkpoint at a 2,048 context; the capstone model must be re-measured.

## Guard (what the job refuses, before the model loads)

`G10_STDIO_SECRET_PATHS` must exist and name the task file given as `--rl-tasks`; with the local runner the isolation
preflight must pass (a sandbox uid cannot read the file, cannot open an IP socket); a known pass and a known wrong answer must
score 1 and 0; and a program that opens the task file and prints the expected output of the test it is given must score 0
on the runner used. Case C of the log: a wrong secret path is refused in 0.0 s (0.90 s with Python's start-up), exit 1, no
model loaded. Case A: attack score 0 on docker (the file is not in the container), guard 1.0 s.
