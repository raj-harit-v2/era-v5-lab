## Resource basis and limits

Step 2 (measured on the M1 Pro laptop, shards 0-3, one process each): 10.8-15.1 s per shard, reading one pack and its
sidecar; about 15 minutes for 70 shards one after another, less in parallel. It adds no memory beyond one sidecar map.

Measured: 66 independent shards on Civo (16 vCPU, 32 GB), 2 h 34 m 50 s including disk pauses and OOM recovery. Eighteen concurrent shards exceeded memory; the remaining run used 12 workers. This request uses six workers and asks for 32 GB RAM. The exact TSAI configuration has not been measured. The 480-minute limit is a cap, not a promised runtime; a roughly linear worker-scaling estimate is 5-8 hours, with substantial uncertainty from source variation, I/O and startup.

The full pipeline retains intermediate files and packs. The 240 GB disk request is an estimate, not a measured peak for this retention mode; allow input staging and all output bytes. The Civo observed peak (64.23 GiB) used per-shard deletion and does not establish the full-retention disk requirement. Results returned to Git are small reports only; pack bytes must go to TSAI storage. No claim that the packs are currently stored there.
